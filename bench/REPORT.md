# ReAct vs 보조-뇌: 약한 모델에서 비교 (2026-10-01)

## 한 줄 결론

**현재 보조-뇌(커밋 `fccaa1e`)는 약한 모델에서 ReAct보다 정확도가 낮고, 토큰은 2.3~2.6배 더 씁니다.**
특히 보조-뇌에 유리하게 고른 진단 과제에서 더 크게 졌습니다(0/24 대 19/24). 패배의 기제는 측정으로 확인했습니다(아래 4절).


## 4. 왜 졌나 — 기제를 쟀다

진단 과제에서 틀린 답이 보고서의 미끼 부품("교체 권고")과 같은 경우를 셌습니다.

| 조건 | 방식 | 틀린 답 | 그중 미끼 |
|---|---|---:|---:|
| Haiku 생각 끔 | ReAct | 5 / 24 | 3 |
| Haiku 생각 끔 | 보조-뇌 | 24 / 24 | **22** |
| Haiku 기본 | ReAct | 0 / 12 | 0 |
| Haiku 기본 | 보조-뇌 | 10 / 12 | **10** |

기록을 따라가 보면 순서가 매번 같습니다.

1. 보조-뇌 프로토콜은 "아는 것을 `fact`로 적고, 주장은 `because`로 근거를 대라"고 요구한다. 그래서 약한 모델은 **과제 문장을 사실로 옮겨 적는다.** 낡은 보고서의 "R4 정상"도 사실이 된다.
2. 그 "사실"에서 첫 호출 만에 미끼 부품을 답으로 이끌어 낸다.
3. 보조-뇌는 "도구가 있으면 답이 도구 관측에 한 번은 닿아야 한다"고 막는다. 그러면 모델은 **미끼 부품 하나만** 재고, 그 관측("D5 출구 낮음": 참이지만 판정에는 부족함)을 근거에 끼워 통과한다.

반면 ReAct는 매 턴 행동 하나를 강제합니다. 칠판에 적을 "사실"이 없으니 보고서를 사실로 굳히지 않고, 측정을 이어 가다가 맞힙니다.

**정리하면, 지금의 보조-뇌는 약한 모델에게 두 가지 짐을 더 지웁니다.** 하나는 JSON 연산을 쓰는 일이고(호출당 출력 457 대 241토큰, 중앙값), 다른 하나는 **자기가 적은 것을 믿게 만드는 구조**입니다. TMS는 근거의 *모양*만 검사하고, 근거로 쓰인 사실이 *낡았는지*는 모릅니다.

## 5. 버린 측정

- **Sonnet 5.5:** 호출 274번 중 187번이 "safeguards flagged this message" 오류였다(양쪽 모두). `bench/results/discarded/`에 남겨 두었지만 결론에는 쓰지 않는다.
- **Opus 5.5:** ReAct 실행 12개 중 11개에서 같은 오류가 났고, 보조-뇌 쪽은 0건이었다. 보조-뇌가 11/12를 맞혔지만, **기준선이 망가져서 비교로는 쓸 수 없다.** 왜 ReAct 기록이 걸리는지는 모른다(첫 호출보다 기록이 쌓인 뒤에 많이 걸렸다).

그래서 **강한 모델에서 보조-뇌가 나은지에 대해서는 할 말이 없습니다.**

## 6. 확인하지 않은 것

- 실제 소형 모델(1~3B). Haiku 생각 끔은 그 대용일 뿐이다.
- 외부 표준 벤치마크(HotpotQA, ALFWorld). 데이터 서버가 막혀 있어서 과제는 전부 내가 만들었다.
- 과제는 계열마다 12개다. 진단 과제의 차이는 커서 표본이 작아도 방향이 분명하지만, multihop의 0.96 대 0.88은 구간이 넓다.
- ReAct 프롬프트는 조정하지 않았다(원 논문 꼴에 예시 하나). 보조-뇌는 개발 시드(0–2)에서 두 번 고쳤다. **조정 기회는 보조-뇌가 더 많이 가졌다.**

## 7. 다음에 할 것 (새 시드 200번대에서 재야 함)

본 실행 결과를 보고 보조-뇌를 고치면, 같은 시드로 다시 재는 것은 시험지를 보고 공부한 셈이 됩니다. 아래는 가설이고, 시드 200번대에서 재야 합니다.

1. **LLM은 지금 상태에 관한 `fact`를 쓸 수 없게 한다.** 사실은 도구와 사람만 만든다. 과제 문장은 장치가 "주어진 진술(출처: 보고서, 시점: 어제)"로 미리 넣는다. LLM이 쓸 수 있는 것은 가정과 주장뿐이다. → 4절의 1단계를 끊는다.
2. **판정 규칙을 TMS에 규칙으로 넣으면, 필요한 관측(입구와 출구 둘 다)이 빠졌을 때 `MISSING_PREMISE`가 난다.** 지금은 규칙이 LLM 머릿속에만 있어서 보조-뇌가 "무엇이 빠졌는지"를 모른다. → 4절의 3단계를 끊는다.
3. **한 턴에 연산 하나**(ReAct처럼). JSON 출력 부담과 한 번에 결론까지 내닫는 일을 줄인다.
4. 이렇게 고친 뒤에도 토큰이 ReAct의 2배 언저리라면, "보조-뇌가 토큰을 아낀다"는 처음의 가설은 **버려야** 한다. 남는 가치는 정확도뿐이다.
